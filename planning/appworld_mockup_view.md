## Mockup contract (do not invent a new one)

Live UI already expects:

```js
// tree node
{ id, label, count, children }   // leaves: children: []

// document
{ id, title, domCluster, fnCluster, path, body }
// domCluster / fnCluster are LEAF node ids in the matching tree

TREES = { domain: DOMAIN_TREE, function: FUNCTION_TREE }
// root id is "root"
```

Ledger `evaluate()` and counts use `DOC_PATHS` (ancestor id arrays). Unique ids are enough for that path.

Two mismatches the adapter must absorb (do not “fix” them in the artifacts):

1. **Cut shape.** Cuts keep `canonical_node_id`, `children`, and `direct_leaf_node_ids` on the same node. The mockup only walks `children`. Promote `direct_leaf_node_ids` into `children` the way `walk_cut_json` does in `orchard/src/orchard/cuts.py`. Do not invent “other” nodes. Do not drop internals.
2. **Prefix slugs.** Leftover `executeSearch` / fill-bar code still does `clusterId.startsWith(nodeId)`. Dummy ids were hierarchical (`travel` / `travel-beach`). Canonical ids are `member_<hash>` and will not prefix-match. Synthesize **view-only path-prefix ids** from cut ancestry, e.g. `d/7be4a65d/a204cad0/...`. Keep human **labels** from `phase5a_intrinsic` (leaves: `item_id` / title). Do **not** slugify labels into ids — labels collide.

A `canonical_node_id → view_id` map may exist inside the adapter to assign `domCluster` / `fnCluster`. Do not ship it as a product API.

## Adapter recipe

New script: `orchard-view/scripts/adapt_orchard_to_mockup.py`.

Per tree:

- Walk `cut["root"]`.
- Root view id `"root"`, label `"All Documents"`, `count` = `descendant_count`.
- Children = promoted leaves + recursive internals.
- Internal label = `phase5a_intrinsic` mapping for that `canonical_node_id`.
- Leaf label = document `title` / `item_id`.
- View id = path-prefix slug from ancestry (tree letter + short hash segments). Child ids must `startsWith` parent ids (except the synthetic `"root"`).

Per document:

- `id` = `item_id`
- `title` = document title
- `body` = `text` (optionally prefix `app_name` so term search hits the app)
- `domCluster` / `fnCluster` = that item’s **leaf view id** in each adapted tree
- `path` = domain label trail for the preview pane (`Parent → Child → Leaf`)

Output JS must assign:

```js
const DOMAIN_TREE = ...;
const FUNCTION_TREE = ...;
const TREES = { domain: DOMAIN_TREE, function: FUNCTION_TREE };
const DOCS = [...];
```

No `FN_MAP`. No `generateDocs`. No `ORIGINAL_DOCS`.

Sanity before writing JS (hard stop if any fail):

- 457 docs
- every doc has both `domCluster` and `fnCluster`
- every adapted leaf id is referenced by at least one doc
- domain root children length is **9**
- function root children length is **3**

Write to `artifacts/appworld/view/mockup_data.js`. Use `json.dumps` into a JS file; keep it valid JS (no Python `True`/`None`).

## Pitfalls

- `file://` + `fetch(json)` will fail. `<script src>` of a sibling/relative JS file is the load path.
- Both trees share the same root membership hash in the orchard packet. View ids must still be distinct across trees (`d/...` vs `f/...`) so `findNode` / ledger node ids do not collide.
- `direct_leaf_node_ids` on an internal that also has `children` must become sibling leaf nodes in the mockup tree, not be dropped.
- Do not use `walk_cut_json` as the on-disk artifact. You may call it in the adapter, then remap ids/labels into `{id, label, count, children}`.
- Header `activeCount` 847 is HTML, not only JS. Update both the badge and the status bar string.
