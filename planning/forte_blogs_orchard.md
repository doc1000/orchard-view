## Objective (in this order)

1. **Load** posts as orchard `Document`s (frontmatter → metadata/title; body → text; stem → `item_id`).
2. **Train CODE** with existing orchard coding only: convert the YAML to
   `orchard_taxonomy_definition_v1`, `TaxonomyModel.fit()` on synthetic chunks plus
   heading-explicit real sections, then `transform()` the full 279-post corpus.
3. **Build** `OrchardBuilder(taxonomies=[fitted_code], include_semantic_with_taxonomies=True)`.
   No Domain / Function taxonomies. Semantic = default TF-IDF. gpt-4.1-mini is not an embedder.
4. **Cut** both trees with the same Calinski-optimal params as AppWorld.
5. **Label** cut-visible internal nodes with `gpt-4.1-mini-2025-04-14`, then `import_labels`.
   Leaves keep post titles.
6. **Adapt** cuts into the existing mockup JS shape (semantic → domain slot, CODE → function slot).
7. **Copy** `visual_search_appworld.html` → `visual_search_forte.html` and pack a standalone folder.

## CODE training

Convert YAML → `orchard_taxonomy_definition_v1` JSON (`name: "CODE"`,
`label_order: capture|organize|distill|express`). Derive `cues` from each label’s
typical-action phrases.

`TaxonomyModel.fit(train_docs, labels_by_item_id)` on:

1. The 20 synthetic `training_chunks` (5 per class) as `Document`s with ids like `seed.capture.0`.
2. **Heading-explicit real sections**, not whole unlabeled posts. Scan `H1`–`H3` for a
   **single** CODE stage word (`Capture` / `Organize` / `Distill` / `Express`). Take the
   section body until the next heading. Skip mixed headings such as “Organize and Distill”.
   Known gold: `posts/0027-building-a-second-brain-the-definitive-introductory-guide.md`.

Write `artifacts/forte_blogs/training/manifest.json` listing every training item_id,
label, and source (yaml chunk vs post path + heading). Synthetic chunks are
training-only and are **not** orchard leaves. The fitted classifier `transform()`s
the full 279-post corpus.
